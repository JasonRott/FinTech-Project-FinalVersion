## 1. 核心設計哲學：兩層式（screening + optimization）

**理由**：文獻（Galagedera 兩階段 DEA→投組、MDPI 2023 MCDM、TOPSIS+GP）一致採用「MCDM/DEA 負責排序篩選，另一個最佳化器負責配重」。把偏好分數直接當最佳化目標（舊 Arm A）會落入 weighted-sum scalarization 的缺陷：報酬項用排名分數、和真實報酬脫鉤。

**決策**：偏好分數降級為「評估指標 + 篩選」，最佳化器升級為 mean-variance + 風險預算（Arm B）。偏好透過參數（λ、風險預算、報酬傾斜）進入最佳化，而非直接被最大化。

---

## 2. 兩臂賽馬（Arm A vs Arm B）

**理由**：事先無法知道哪個目標函數的樣本外（OOS）成績最好，所以不賭單一方案，保留 baseline 當對照，用 rolling backtest OOS + 偏好勝率當裁判。避免 overfit 單一想法。

## 3. 成敗歷程（時間序）

### ✅ 成功 / 已確立
- **True portfolio MaxDD**（2026-05-25）：MaxDD 改用真實 NAV 路徑，取代單檔線性加權 proxy。
- **視覺化／求解器統一算術平均**：Sharpe 定義需算術平均；幾何低估分子。報表保留兩口徑。
- **DEA 選項 A**：`Out_Return` 拆成 `Out_CAGR`+`Out_Div`，成長股不再被股息平均稀釋（候選池 DEA≥0.8 從約原本擴增到 75/302）。
- **殖利率偏好比例加權**：μ 中的殖利率依使用者 `Return_Div/Return_CAGR` 比例加權，而非 1:1。比例由偏好權重動態計算，非硬寫。
- **V-1 / V-6 偏好驗證圖**：用既有 `preference_scores_df` 畫出「偏好分數樣本外預測力」與「偏好勝率時間序列」。發現偏好分數能預測「偏好滿足度」(r≈0.6)，但不能預測「報酬」(r≈0)。

- **Arm C v1（最小變異核心 + 偏好傾斜）= 綜合解**（2026-06-05）：`min ½wᵀΣw − τ·(wᵀs)`，τ=0.1。Sharpe 0.666（>等權 0.622、>Arm A 0.464）、MaxDD -14.2%、偏好勝率 72/100/91%（≈Arm A 的 83/100/88%）。**在財務上全面優於 Arm A，偏好滿足度幾乎追平，並打敗天真等權。核心張力（偏好滿足 vs 財務效率）被 τ 旋鈕解決。**

### ❌ 失敗 / 負面結果（同樣寶貴）
- **Arm B v2（DEA前25% + Ledoit-Wolf + 算術 + 股息0.25）反而更差**（2026-06-04）：
  - Preference_Driven Sharpe 0.366（v1 是 0.510、Arm A 0.464）、波動 17.10%（比 VOO 還高）、MaxDD −29.82%。用更高風險換到更低報酬。
  - **診斷**：(a) 算術 μ 比幾何激進（追高均值高波動標的）；(b) 股息降權移除了 v1 意外的防禦傾斜；(c) Ledoit-Wolf 只收縮共變異數、沒收縮**均值**，而均值才是主要雜訊源；(d) 波動預算 30% 從未綁定。
  - **教訓**：μ（期望報酬）的估計品質才是 OOS 的真正瓶頸。共變異數收縮必要但不充分。→ 導向「均值收縮 / Black-Litterman」。

### 🔁 決議不做 / 暫緩
- 相關性分群門檻 0.99 維持（0.99 幾乎等於同指數，去重合理、極少誤刪）。
- 交易成本暫不加（演算法未穩定前加入只會更差）。

## 4. 參考資料（學理）

### 4.1 1/N 之謎（Equal-Weight Puzzle）
- DeMiguel, Garlappi & Uppal (2009), *Optimal Versus Naive Diversification: How Inefficient is the 1/N Portfolio Strategy?*, Review of Financial Studies.
- 結論：在樣本外，天真的等權（1/N）投組常常打敗 mean-variance 最佳化，因為後者對「期望報酬與共變異數的估計誤差」極度敏感。
- **本專案重現此現象**：EqualWeight（Sharpe 0.622）持續贏過所有最佳化臂（Arm A 0.464、Arm B v2 0.366）。這正是「估計誤差」主導 OOS 表現的證據，也是我們投資「估計品質升級（收縮 / Black-Litterman）」的實證理由。

### 4.2 估計誤差與收縮
- Ledoit & Wolf (2004), *Honey, I Shrunk the Sample Covariance Matrix* — 共變異數收縮。
- Jorion (1986), *Bayes-Stein Estimation for Portfolio Analysis* — 期望報酬（均值）收縮。
- Black & Litterman (1992) — 用市場均衡先驗 + 投資人觀點產生後驗期望報酬；本專案視為「偏好整合」的天然框架（drop-in 取代 μ，求解器不變）。

### 4.3 偏好→效用的四種學派（詳見 `04`）
線性加權加總 → 均值-變異數期望效用 → 目標規劃（約束式）→ 兩層式（MCDM 篩選 + 正規最佳化）。本專案從第一種往第二/四種升級。

## 4.5 重要觀念：排名式傾斜 vs 原始 μ（為何 Arm C 不會重演 v2）

使用者提問（2026-06-05）：Arm C 用 `User_Pref_Score`（含 `Norm_Return_CAGR`）當傾斜目標，不就把資本利得噪音又丟進求解器？

**答：技術上噪音確實會經 `w ∝ Σ⁻¹·s` 流入並被 Σ⁻¹ 放大，光「s 有界」不能完全免疫。** 但與原始 μ 丟進 mean-variance 有四個關鍵差異，使其大幅馴服、不會重演 Arm B v2 災難：
1. 排名+縮尾（1%/99%）→ 無單一離群 ETF 主導；
2. 排名壓縮 → 追不動報酬「水準」差異；
3. 只是 s 九維之一，且 s 只是 τ 控制的小傾斜（非主目標）；
4. Ledoit-Wolf 使 Σ⁻¹ 良態，放大有限。

**深層誠實**：資本利得排名不預測未來報酬（V-1 右圖 r≈0）。傾斜它＝「符合使用者嘴上要的」，不是「真能多賺」。對報酬導向使用者，這是誠實的極限：穩健核心上受控傾斜，不假裝排名能預測報酬。

**決議**：不靠猜，用實驗——sweep `s_full`（含 CAGR 排名）vs `s_noCAGR`，OOS 決定資本利得排名是幫忙還是傷害。

## 4.7 標竿決議：VT 為「無偏好基準/錨」，VOO 為「目標/天花板」（2026-06-05）

- VOO 是 100% 大型美股、集中科技 → 是「難打敗的目標/aspiration」，不適合當基準。
- **VT（全球市值加權）= 更好的基準與無偏好錨**：分散度更高、less tech、風險更低、更接近「真正的市場組合」。理論上 VT ≈ CAPM/Black-Litterman 的市場均衡先驗，所以當錨最有理。
- **重訂成功定義**：偏好驅動投組目標 = 風險盡量接近 VT、報酬盡量高於 VT。無偏好基準設為 VT 表現。

## 4.8 關鍵釐清：拿掉 CAGR 排名後，資本利得仍透過「共變異數」貢獻（#4）

- s_noCAGR 把資本利得的「期望報酬/排名」訊號從傾斜中移除。
- **但資本利得仍經 Σ（共變異數）進入最小變異核心**——Σ 由資本利得日報酬的「共同波動」估計而來。故資本利得仍貢獻「風險結構」，只是不再貢獻「報酬水準」訊號。
- 加上候選池層（DEA Out_CAGR + 分群）仍用到資本利得。
- → 這正是正確的分工：資本利得歷史用在它擅長的（估計共變異/風險，較穩定），不用在它不擅長的（預測期望報酬水準）。

## 4.9 ★核心觀念★ 報酬來自「承擔系統性風險」，不來自「預測」（2026-06-05，重大）

### 為什麼目前「換不到報酬」
兩個設計選擇都在壓低報酬：
1. **核心是最小變異** → 坐在效率前緣最左下角，天生低風險低報酬。
2. **傾斜用「偏好排名」而非「預測性報酬」** → τ 加大只換到「排名高的標的」，非「會漲的標的」；加風險買不到報酬。
→ 風險只會白白增加，因為沒有任何「風險→報酬」的真實連結。

### 關鍵真理
> **可靠的超額報酬來自「承擔有風險溢酬的系統性風險」(risk premia)，不來自「猜哪檔會漲」(forecasting μ)。**
- 猜個別 μ 不可靠（1/N 之謎、估計誤差）→ 選贏家死路。
- 但「股票風險溢酬 / 因子溢酬」真實且穩健 → 承擔更多 beta/因子曝險，平均換到更高**絕對**報酬（代價是更高波動），不需預測。

### 設計含義：穩健核心應 profile-dependent
| 使用者 | 核心錨點 | 邏輯 |
|---|---|---|
| 保守型 | 最小變異（前緣左下） | 要低風險，核心與偏好一致 |
| 平衡型 | 市場組合（≈VT，beta≈1） | 拿完整股票溢酬 |
| 報酬導向 | 高 beta / 目標高波動點（前緣右上） | 用風險預算「買 beta」，拿更多溢酬 |

- 報酬導向使用者：**目標一個較高的波動（≥VT 的 ~15%），在預算內最大化股票/市場曝險**（不是最小化波動、也不是追噪音 μ）。這才是真正的「用風險換報酬」。
- 傾斜訊號改用**比 μ 穩定的 beta / 因子曝險（規模、價值、動能、品質）**，而非歷史 CAGR 排名。

### 誠實的代價（低波動異常）
歷史上低波動資產**風險調整後**報酬更好（這正是最小變異會贏的原因）。所以報酬導向使用者往上爬 → 拿到更高**絕對**報酬，但 **Sharpe 下降、回撤變大**。這是合理且該被允許的：
- **報酬導向使用者的「成功」要重新定義**：不是「更高 Sharpe」，而是「在可接受風險上限內，拿到盡量高的絕對報酬」（報酬可高於 VT，但 Sharpe 不一定贏 VT）。
- 系統不該用 Sharpe 最大化否決他的選擇，而該讓他在前緣上自選更靠右上的點。

### Black-Litterman 的定位
BL 先驗 = 市場組合（已內含股票溢酬）；報酬導向使用者的「觀點」= 加碼股票/成長因子。BL 給這個傾斜嚴謹的理論框架（drop-in 取代 μ）。

## 5. 目前待解的核心張力

### ★ profile 依賴性：財務 vs 偏好的 trade-off 不是普世的（2026-06-05，重要）
目前所有 τ 校準與 Pareto 前緣都是用「報酬導向的 Neutral_user」算的，這對其他 profile 會失真：
- **報酬導向使用者**：高偏好分數 = 高報酬排名 = 高波動 → 偏離最小變異 → 真的有「財務↓ vs 偏好↑」trade-off（我們觀察到的）。
- **保守型使用者**：高偏好分數 = 低波動/低回撤/低成本 = 正好就是最小變異要的 → **偏好與財務一致，可能沒有 trade-off，甚至 τ↑ 同時改善兩者**。
- 結論：**trade-off 的形狀與最佳 τ 都是 profile-specific**。不可用單一 profile 校準的 τ 套用到所有人。
- 對策：τ→偏好映射前，必須對多個 profile 原型（保守/平衡/報酬導向）各跑 τ sweep，刻畫 trade-off 如何隨 profile 改變。目前只測過一個 profile，是重大覆蓋缺口。

1. **偏好滿足 vs 財務效率**：Arm A 偏好勝率高但報酬差；Arm B 報酬導向但偏好勝率掉。解法：把偏好放進目標參數，讓兩者兼得。
2. **理論正確 vs 估計穩健**：算術 μ 理論正確但樣本估計太激進。解法：對算術 μ 做收縮 / Black-Litterman。
3. **九維偏好多數未進目標**：報酬/風險之外的維度（成本、流動性、分散、情緒）目前只在篩選層作用。

   **決議（2026-06-04）：採方式 (b) — 改為約束/門檻（goal programming）**，由偏好權重映射出門檻值（如「加權費用率 ≤ X」「加權流動性 ≥ Y」「產業 HHI ≤ Z」）。主目標維持報酬/風險，品質維度當「資格條件」不稀釋主目標。

   **優劣權衡（使用者提醒要記錄）：**
   - 優點：(i) 不稀釋報酬/風險主目標；(ii) 偏好真正進入配置層（非只篩選）；(iii) 符合兩層式與文獻。
   - 缺點：**每個約束都是一個要校準的門檻參數**（成本上限、流動性下限、分散下限…），加上既有的 λ、波動預算、收縮 δ、DEA 前 X%、rebalance/lookback，**超參數空間明顯變大**，校準與過擬合風險上升。
   - 對策：先鎖定最少必要約束、用實驗逐一加入並記錄 OOS 影響，避免一次塞太多參數；門檻優先用「相對分位數」而非絕對值，較穩定。
   - 狀態：方向已定，待 Arm C 結構穩定後再逐一加入。
   - **映射方式決議（2026-06-05）：偏好權重 → 約束門檻一律用「百分位數」**（如成本上限 = 候選池費用率的某分位；高成本偏好權重 → 取較低分位＝更嚴）。相對分位比絕對值穩定、隨 universe 自適應。剩下只需決定「權重 → 分位」的對應標準。

## 4.55 穩健性優先 + 未來多窗驗證（2026-06-05 決議）

- 體認：我們只有單一歷史路徑，演算法調太多次必然 overfit 這條路徑。後續一切設計**以 robustness 為首要目標**，勝過追逐單一路徑的高分。
- **未來計畫（等演算法所有設定定案後）**：對多個 lookback 長度與多個 total time window 做 walk-forward / 多段 OOS 驗證，確認結論不依賴單一窗。在此之前的所有數字都應視為「單路徑的指示性結果」。
- 多 profile 驗證：已在 `parameters.USER_PROFILES` 定義 7 個原型（aggressive_growth / return_leaning / balanced / conservative / income / cost_liquidity / diversified_quality），供各自跑 τ sweep，檢驗 trade-off 的 profile 依賴性（見 5 節）。

## 4.57 AHP 權重 vs 手設 profile 權重的一致性（2026-06-05）

問題（使用者提出）：USER_PROFILES 繞過 AHP，之後是否需要校準 AHP 權重與這些手設權重？

- **下游不需校準**：兩者都是 9 維、和=1 的全局權重向量，餵同一個下游（User_Pref_Score、Arm C 傾斜 s），可互換。
- **真正的隱患**：若用 profile **名稱查表**決定 τ，真實 AHP 使用者的權重不對應任何 profile → 沒有他的 τ。
- **決議：「偏好 → τ / 預算 / 門檻」映射設計成「權重向量的函數」g（例如 τ=g(報酬權重, 風險權重)），而非 profile 名稱查表。** 如此 AHP 輸出與手設 profile 都只是「一個權重向量 → 套同一個 g」，自動一致。
- profile 的角色：**刻畫/擬合 g 的代表性取樣點 + 涵蓋權重空間**，非與 AHP 競爭的真理來源。
- 要做的 reconciliation：(1) 確認 profile 涵蓋/包住 AHP 實際可達的權重區域（`return_leaning` 即現行 AHP deterministic 輸出，是錨點）；(2) 注意 AHP 特徵向量權重恆正且兩層結構有比例約束，故極端 profile（如 Div=0）AHP 不可達——實驗/壓測可用，但**最終 g 應定義在 AHP 可達區域**。

## 4.6 方法論決議：超參數 sweep 採「單參數 / OAT」，不做大網格

決議（2026-06-05）：先只 sweep τ（主旋鈕），其他參數固定；後續次要參數用 OAT（一次只動一個），**不做聯合大網格**。
理由：(1) 只有一條歷史路徑（2021–2026），多參數網格在單一樣本上必然過擬合（data-snooping / 研究者自由度，參考 Harvey, Liu & Zhu 2016）；(2) τ 是主旋鈕，其他多半未綁定或寬鬆；(3) 乾淨歸因 + 便宜。真正的聯合調參等有 walk-forward / 多段樣本再做。
